# 实验六：开源工作流自动化与服务集成系统
## 项目说明
本项目使用Node-RED作为工作流引擎，搭配独立FastAPI库存服务，实现订单提交、库存扣减、异常分支处理、幂等校验等核心功能。
## 使用开源项目版本
- Node-RED 5.0.7
- FastAPI 最新兼容版本
- Uvicorn 最新兼容版本
- SQLite 3 内嵌数据库
## 功能清单（全部完成）
1. 双独立进程：Node-RED工作流服务(1880端口) + FastAPI库存服务(8001端口)，均提供/health健康检查接口
2. 工作流输入校验：校验请求编号、商品编号、数量三个必填参数，参数缺失返回400错误
3. HTTP接口调用：工作流通过POST请求调用库存服务/reserve接口，不直接读取库存数据库
4. 多异常分支：
   - 参数缺失/数量<=0：返回400错误
   - 商品不存在：返回404错误
   - 库存不足：返回409错误
   - 重复请求：同request_id不重复扣减，直接返回重复处理提示
   - 编号冲突：同request_id不同请求体返回409冲突错误
5. 商品库存：共10个商品，包含充足库存、低库存、零库存三类测试数据
6. 幂等校验：同一request_id的相同请求不重复扣减库存
7. 查询接口：支持查询所有商品列表、所有已完成扣减记录、按状态筛选记录
8. Web界面：支持订单提交、记录列表展示、状态筛选、提交错误反馈
9. 数据持久化：SQLite存储商品、库存、扣减记录，服务重启后数据不丢失
## 启动步骤
1. 启动Node-RED：在D:\workflow-lab目录运行 `npx node-red`
2. 启动库存服务：进入service目录激活虚拟环境，运行 `uvicorn app:app --host 127.0.0.1 --port 8001`
3. 访问库存服务Web页面 http://127.0.0.1:8001 提交订单、查看记录
## 测试用例
- 正常扣减：{"request_id":"test001","sku":"BOOK","quantity":2} → 成功，剩余库存8
- 重复请求：同request_id再次提交 → 返回"重复请求，已处理"
- 库存不足：{"request_id":"test002","sku":"ERASER","quantity":1} → 返回409库存不足错误
- 参数缺失：缺少request_id字段 → 返回400错误
